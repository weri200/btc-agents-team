# BTC Agents Team · Futures Desk

Binance 코인 선물의 **4시간 추세 돌파를 코드 규칙으로 판정하고, 그 근거와 로컬 AI의 해설을 GUI에서 검토**하는 프로젝트입니다. 자동 주문보다 사람이 분석 과정을 확인하는 경험을 우선합니다.

> **현재 상태: 코드 규칙 판정 + LM Studio 로컬 모델 하나의 해설.** Binance 공개 API의 체결가·마크 가격·펀딩비율·미결제약정·마감 캔들을 수집해 로컬 SQLite에 저장합니다. 매매 판정(롱·숏·관망)은 `signals.py`의 규칙이 서버가 계산한 지표로 냅니다. LM Studio의 로컬 모델 하나는 그 판정이 왜 나왔는지와, 규칙이 보지 않는 위험(펀딩·미결제약정·롱숏 비율·변동성·OpenBB 뉴스·경제 일정)만 설명하며 판정을 바꿀 수 없습니다. 모델이 꺼져 있거나 실패해도 판정은 그대로 나옵니다. 서버를 켠 뒤 처음 페이지를 열면 분석을 자동으로 시작하고, 그 뒤에는 서버의 마지막 분석 결과를 불러옵니다. 완료된 분석의 판정은 SQLite에 저장되고, 이후 수집된 캔들로 채점합니다(`/api/scores`, 기록 화면의 표). `python backtest.py`는 과거 시점(Binance 아카이브로 2020년 9월부터 가능)에 같은 규칙을 모델 없이 다시 적용해 따로 채점합니다. 여러 모델이 토론해 판정하던 이전 구조와 바꾼 이유는 아래 "이전 구조와 바꾼 이유"를 보세요.

## 목표와 현재 결정

- 거래소: Binance. 화면은 USDⓈ-M 무기한 선물을 기준으로 설계했습니다. 현재 차트와 동일한 BTCUSDT·ETHUSDT·SOLUSDT USDT 무기한부터 읽기 전용 수집을 구현했습니다.
- 분석 주기: 4시간봉 마감마다 판정합니다(1일 추세 + 4시간 돌파). 단타 판정은 `rules-v2`에서 뺐습니다(아래 "판정 규칙").
- 판정: 코드 규칙(`signals.py`)이 냅니다. 같은 지표면 항상 같은 판정이고, 백테스트 성적이 곧 그 규칙의 성적입니다.
- 모델: LM Studio의 로컬 모델 하나가 판정 이유와 규칙 밖의 위험만 설명합니다. GPT 등 클라우드 모델은 연결 계획이 없습니다.
- 투명성: 규칙의 조건별 값, 청산 기준, 해설, 자료 기준 시각을 표시합니다.
- 자동 주문: 현재 범위에 포함하지 않습니다.
- TradingAgents(TauricResearch/TradingAgents)는 연결하지 않습니다. 비슷한 여러 모델 팀 구조를 직접 만들어 썼다가 폐기했습니다.

## 이전 구조와 바꾼 이유

**이전 구조 (`local-team-v5`·`v6`, 2026-10 이전):** 역할마다 다른 로컬 모델 5개가 판정했습니다. 기술 분석가(Mistral Nemo)·파생상품 분석가(Phi-4)·뉴스·거시 분석가(EXAONE)·반대 검토자(Gemma 4)가 각자 롱·숏·관망을 내고, 종합 판정자(Qwen 27B)가 의견을 모아 최종 판정을 냈습니다. 스윙 규칙(`breakout-volume`)은 기술 분석가의 프롬프트에 글로 적혀 있었고, 인용 수치가 틀리면 관망으로 바꾸는 검증이 있었습니다.

**왜 안 좋았나 (BTCUSDT 90일 백테스트 중 351개 시점, 2026-08-21~10-17):**

- **종합 판정자가 351번 모두 관망**이었습니다. 파생상품·거시 분석가도 전부 관망이었고(거시는 백테스트 자료가 없음), 판정자 프롬프트가 "의견이 갈리면 관망"이라 기술 분석가 혼자 롱을 내면 늘 막혔습니다. 구조상 매매 신호가 나올 수 없었습니다.
- **기술 분석가는 프롬프트의 규칙을 지키지 않았습니다.** 롱·숏 342건 중 332건이 규칙 조건(추세 + 20봉 돌파 + 거래량)이 맞지 않는 시점이었습니다. "고점보다 종가가 높은가", "거래량 비율이 1을 넘는가" 같은 숫자 비교를 모델이 자주 틀렸습니다. 그 결과 적중률 34%, 평균 +0.04%, 점수 −0.32로 관망만 할 때(−0.25)보다 나빴습니다.
- 같은 규칙을 코드로 계산하면 신호는 10건이었고 4건 적중, 평균 +0.39%였습니다(수수료 제외). 건수가 너무 적어 우위를 판단할 수는 없지만, 백테스트 성적이 규칙이 아니라 모델의 실수를 재고 있었다는 뜻입니다.
- 시점마다 모델 5개를 번갈아 불러와 시점 하나에 약 4~5분, 351개에 하루 이상 걸렸습니다.

**바꾼 방향:** 판정은 코드가, 해설은 LLM이 맡습니다.

- 매매 판정(롱·숏·관망)은 `signals.py`가 서버 지표로 계산합니다. 같은 숫자면 항상 같은 판정이고, 백테스트 성적이 곧 그 규칙의 성적입니다.
- LLM은 모델 하나로 줄였고, 판정 이유와 규칙이 보지 않는 위험(펀딩·미결제약정·롱숏 비율·변동성·뉴스·경제 일정)만 씁니다. 응답에 판정 칸이 없어 판정을 바꿀 수 없습니다.
- 백테스트는 모델 없이 돌아 시점 하나에 1초 안팎이고, 몇 년치도 짧게 검증할 수 있습니다.
- 순서: 규칙에 실제 우위가 있는지를 `research.py`로 길게, 수수료를 포함해 먼저 확인합니다. 우위가 없으면 해설을 다듬어도 의미가 없습니다. 모델에게 "이번엔 넘기자"는 거부권을 주는 것은 거부권이 있을 때와 없을 때를 백테스트로 비교해 성적이 좋아질 때만 넣습니다.

## 빠른 시작

Python 3.10 이상과 표준 라이브러리로 로컬 서버를 실행합니다. 별도 pip/npm 패키지 설치나 빌드는 필요 없습니다.

```sh
git clone https://github.com/weri200/btc-agents-team.git
cd btc-agents-team
python server.py
```

브라우저에서 `http://127.0.0.1:8876`을 엽니다. 포트를 바꾸려면 `python server.py --port 8877`을 사용하세요. 같은 포트를 이미 다른 서버가 쓰고 있으면 서버가 오류 메시지를 내고 종료합니다. Windows에서 두 서버가 같은 포트에 겹쳐 뜨는 것을 막기 위해서입니다. 단순 정적 서버나 파일 직접 열기로는 수집 API가 동작하지 않습니다. 보고서 이력과 테마 설정은 주소·포트별 브라우저 저장소에 보관됩니다.

검사에는 Node.js가 필요합니다. 별도 npm 의존성은 없습니다.

```sh
node test.cjs
node test_market_ui.cjs
node test_opinions.cjs
python -m unittest -v
node --check dist/app.js
node --check dist/model.js
node --check dist/market.js
```

규칙 판정과 해설, 예시 보고서, 실제 분석 보고서 형식, 잘못된 날짜·판정·URL·중복 카드 ID 등의 거절을 검사합니다.

`dist/`는 빌드 산출물이 아니라 현재 직접 관리하는 정적 소스입니다.

GUI는 밝은 중성색 배경, 시스템 글꼴, 파란색 강조, 여백과 카드 위계를 중심으로 구성합니다. 분석 데스크·판단 이력·연결 및 구성·상세 창에 공통 스타일을 적용하며, 모바일에서는 메뉴와 카드를 재배치합니다. Apple 기기에서는 시스템 글꼴을 사용하고 Windows에서는 Segoe UI·맑은 고딕으로 표시합니다.

## 도구 구성

| 도구 | 상태 | 역할 |
| --- | --- | --- |
| Binance API | 구현됨 | 시세·캔들 수집, 분석 시 펀딩·OI·롱숏·테이커 이력 |
| LM Studio | 구현됨 | 로컬 모델 하나가 판정 이유와 규칙 밖의 위험을 해설, 진행 상황 |
| 판정 채점 | 구현 | 완료 보고서를 저장하고 이후 캔들로 적중률·평균 수익률 계산 (직접 구현) |
| 백테스트 | 구현 | 4시간 간격 과거 시점을 Binance REST와 아카이브로 재현해 같은 규칙을 모델 없이 적용하고, 실시간과 따로 채점 (`backtest.py`) |
| OpenBB | 구현됨 | 해설 모델용 미국 국채 금리(Fed), VIX·S&P500(CBOE), 나스닥100·주요 경제 일정·뉴스(Nasdaq). 키 없는 공급자만 사용 |
| FRED | 보류 | CPI·PCE 등 발표 수치. 무료 API 키가 필요하며 키 입력 기능은 아직 없음 |
| Binance 과거 데이터 | 구현됨 | `data.binance.vision` 일별 미결제약정·롱숏 비율(5분)을 백테스트용으로 받아 `data/archive/`에 보관 |
| NautilusTrader | 보류 | 규칙 판정에 비용·펀딩·슬리피지·체결 가정을 넣은 백테스트 |
| CCXT | 제외 | Binance 직접 호출로 대체. 여러 거래소 비교나 주문이 필요해지면 재검토 |
| TradingAgents | 제외 | 여러 모델이 토론해 판정하는 구조는 판정이 규칙을 따르지 않아 폐기 (아래 "이전 구조와 바꾼 이유") |

GPT 등 클라우드 모델은 연결 계획이 없으며, 시장 데이터를 외부 모델로 보내지 않습니다. 각 라이브러리의 버전·호환성과 공급자별 데이터 접근 권한은 실제 연동 단계에서 확인합니다.

판정은 4시간·1일 봉, 진입가는 15분봉, 청산 확인은 1시간봉을 씁니다. 5분봉은 수집·표시만 합니다.

## 보고서 형식

전체 예시는 `example-report.json`, 검증 규칙은 `dist/model.js`의 `validate()`를 확인하세요.

- `schemaVersion`: `1`
- `id`, `symbol`, `asOf`, `promptVersion`: 보고서 식별 정보
- `exchange`: `Binance`
- `market`: `USDⓈ-M perpetual`
- `mode`: `demo`, `analysis`, `backtest`
- `horizons.swing`: 4시간 추세 돌파 판정(키 이름은 이전 채점과 맞추려고 `swing`으로 둠). `rules-v2` 이전 보고서에는 `horizons.intraday`(단타)도 있으며, 있으면 같은 규칙으로 검사합니다.
- 주기별 `verdict`(코드 규칙 판정), `rule`(규칙 이름), `summary`(해설 또는 코드 문장), `agreement`(조건별 값), `disagreement`(규칙 밖의 위험), `condition`(청산 기준), `explainer`(해설 모델, 없으면 null), `agents`
- 카드별 `id`, `name`, `role`, `verdict`, `summary`, `evidence`, `counter`, `invalidation`, `model`, `sources`. 지금은 규칙 판정 카드(`id: rule`) 하나입니다. `rule`이 없는 이전 보고서는 LLM 종합 판정자 형식으로 표시합니다.
- 판정: `long`, `short`, `wait`
- 출처: `title`, `url` (HTTP/HTTPS 또는 null), `asOf`

날짜에는 시간대가 필요하며 UI는 한국 시간으로 표시합니다. `mode: analysis`는 파일 작성자의 선언일 뿐, 실제 AI 실행이나 내용 정확성을 인증하지 않습니다. 파일은 최대 500KB이며 가져오기는 서버 업로드 없이 브라우저에서 처리합니다.

## 시장 차트

TradingView 공식 Advanced Chart 위젯으로 Binance USDT 무기한 BTC·ETH·SOL 차트를 제공합니다. 4시간봉으로 열리며 봉 간격은 차트 위쪽 도구 막대에서 바꿉니다. 한국 시간으로 표시됩니다. 인터넷 연결 및 외부 위젯 제공 상태에 의존합니다. 차트 선택은 데모 보고서 선택과 독립적이며 차트 데이터로 AI 판정을 생성하지 않습니다. 테마를 실제로 바꿀 때만 차트를 다시 불러옵니다. 예전에는 페이지를 열 때 같은 테마가 다시 설정되면서 차트가 두 번 만들어졌고, 첫 차트가 불러오는 중에 지워져 가격·시간 축이 잘리는 일이 있었습니다.

차트 위의 **지표** 메뉴에서 이동평균(SMA), EMA, 볼린저 밴드, VWAP, RSI, MACD, 스토캐스틱 RSI, ATR, 일목균형표, 슈퍼트렌드, 파라볼릭 SAR, 돈치안 채널, 켈트너 채널, 스토캐스틱, DMI(ADX 포함), CCI, MFI, OBV, 윌리엄스 %R을 고를 수 있습니다. 고른 지표는 브라우저에 저장되고(`futures-desk-studies`), 지표 옆 칸에 입력한 기간·배수 등 세부 설정도 저장됩니다(`futures-desk-study-inputs`). 세부 설정은 TradingView 위젯이 실제로 반영하는 SMA·EMA·볼린저 밴드·RSI·ATR·돈치안·켈트너·파라볼릭 SAR·CCI·MFI·윌리엄스 %R에만 있고, 칸을 비우면 TradingView 기본값입니다, RSI·MACD처럼 아래에 별도 창이 생기는 지표를 고르면 그 수만큼 차트가 높아집니다. 목록에 없는 지표는 차트 위쪽 툴바의 TradingView 지표 버튼으로 추가할 수 있지만, 새로고침하면 사라집니다. 차트 지표는 화면 표시용이며 판정에 쓰는 지표는 서버가 따로 계산합니다.

## 실제 수집 데이터 — 1단계

- `GET /api/market?symbol=BTCUSDT` (ETHUSDT·SOLUSDT도 지원). API 키 없이 공개 시장 데이터만 읽습니다.
- `/fapi/v1/time`, `/fapi/v2/ticker/price`, `/fapi/v1/premiumIndex`, `/fapi/v1/openInterest`, `/fapi/v1/klines`를 사용합니다.
- 차트 코인을 선택하면 수집 종목도 바뀝니다. 분석 데스크가 보이는 동안 60초마다 갱신하고, 같은 종목은 30초 동안 캐시합니다. 수동 버튼으로도 요청할 수 있습니다. 브라우저를 닫으면 주기 수집이 중단됩니다.
- 5분·15분·1시간·4시간·1일 봉을 각 최대 200개 가져옵니다. 거래소 기준 시각 이전에 마감된 봉만 저장하며, 중복·누락·순서·OHLC·숫자 유효성을 검사합니다. 진행 중인 봉은 제외합니다.
- 가격·수량·비율은 API의 십진수 문자열을 보존합니다. UI는 펀딩비율에 100을 곱해 %로 표시합니다. 펀딩비율은 API의 `lastFundingRate`이며 실제 계좌 지불액이나 확정된 다음 정산율로 간주하지 않습니다. OI 단위는 해당 기초 코인입니다.
- 항목별 거래소 시각, PC 수집 시각, 수집 소요시간, PC-거래소 시계 차이를 기록합니다. 서로 다른 요청이므로 모든 항목이 동일 시점의 원자적 스냅샷은 아닙니다. 오래된 수급·시계 차이·수집 지연은 경고합니다.
- `data/market.sqlite3`의 `candles`는 종목·간격·시작시각으로 중복 저장을 막습니다. 채점이 이 캔들을 읽습니다. 수집 요약(시세·수급)은 다시 읽는 곳이 없어 저장하지 않습니다(이전 DB의 `snapshots` 표는 남아 있어도 쓰지 않음). 한 번의 수집은 트랜잭션으로 저장하며 부분 실패는 성공으로 취급하지 않습니다. DB는 Git에서 제외됩니다.
- 네트워크 실패·429/418 요청 제한·저장 실패는 화면에 오류로 표시합니다. 제한 시 Retry-After 동안 재호출을 막습니다. 과거 수치를 새 값으로 대체하거나 데모 데이터를 실제 데이터로 반환하지 않습니다.
- 로컬 서버는 127.0.0.1에만 바인딩하며 외부 Origin·Host와 저장 DB의 웹 접근을 거절합니다.
- 아직 없는 기능: 과거 전체 이력 백필, 장기 펀딩/OI 시계열 백필, 주문. 최근 200개 봉 수집을 장기간 전략 검증용 완전한 데이터셋으로 간주하지 않습니다.

공식 API 근거: https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data

## 의견 표시

데스크톱에서는 차트 오른쪽에 4시간 추세 돌파 최종 판정을 표시하고, 좁은 화면에서는 차트 아래로 배치합니다. 최종 판정 카드에는 판단(해설)·조건(규칙의 조건별 값)·위험(규칙 밖의 위험)·청산(익절·손절 가격)을, 그 아래 규칙 판정 카드는 최종 판정과 같은 너비로, 판단·규칙 조건과 값(세 조건 모두)·청산 기준·규칙 밖의 위험·사용한 자료를 카드 안에 모두 보여줍니다. 이전 보고서의 팀원 카드는 예전처럼 상세 창으로 봅니다. 분석 데스크 아래의 **매매 규칙** 표는 규칙의 세 조건과 진입·청산 기준을, **연결 및 구성** 화면은 규칙 버전(`rules-v2`)을 요약합니다. 규칙을 바꾸면 `signals.py`와 함께 이 표(`dist/index.html`)도 고쳐야 합니다. 차트와 보고서 종목이 다른 경우 안내하며 데모·파일 보고서·로컬 분석 결과를 구분합니다. 로컬 분석 결과는 생성 시점의 스냅샷이며 자동 갱신되지 않습니다.


## OpenBB 뉴스·거시 자료

OpenBB는 서버 의존성이 아닙니다. 프로젝트 안의 가상환경(`.venv`, Git 제외)에 설치하고, 서버가 분석할 때 `openbb_bridge.py`를 그 가상환경의 Python으로 따로 실행해 결과(JSON)만 받습니다. 서버는 계속 표준 라이브러리만으로 동작하며, OpenBB가 없거나 실패해도 판정과 해설은 그대로 나오고 경고에 이유를 표시합니다. 뉴스·거시 자료는 판정에 쓰지 않고 해설 모델의 위험 설명에만 씁니다.

```sh
python -m venv .venv
.venv\Scripts\python -m pip install openbb
```

macOS·Linux에서는 `.venv/bin/python`을 씁니다. 다른 위치의 Python을 쓰려면 환경 변수 `OPENBB_PYTHON`에 경로를 지정합니다. 처음 실행할 때 OpenBB가 확장을 빌드하느라 시간이 더 걸리고, 이후에도 불러오는 데 약 15~20초가 걸립니다.

API 키가 필요 없는 공급자만 사용합니다(OpenBB 5.0 기준 공급자별 명령).

| 자료 | 공급자 · 명령 | 서버가 만드는 지표 |
| --- | --- | --- |
| 미국 2년·10년 국채 금리 | Fed `federal_reserve.treasury_rates` | `macro.us2yPct`, `macro.us10yPct`, 5일 변화(bp), 10년-2년 금리차 |
| VIX, S&P500 | CBOE `cboe.index.historical` | `macro.vix`, 1일·5일 변화율 |
| 나스닥100 | Nasdaq `nasdaq.index.historical` | 1일·5일 변화율 |
| 경제 일정 | Nasdaq `nasdaq.economy.calendar` | 분석 시각 전 24시간~후 72시간의 미국 주요 지표(CPI·고용·FOMC·GDP 등) |
| 뉴스 | Nasdaq `news.company` (IBIT·COIN, ETH는 ETHA, SOL은 BSOL) | 최근 7일, 코인 관련 단어가 있는 기사 최대 8개 |

- 일별 자료는 분석 시각(Binance 서버 시각)의 날짜 이후 값을 버립니다. 경제 일정은 분석 시각 이후 항목의 발표 결과를 지우고 "예정"으로만 넘겨, 미래 정보가 들어가지 않게 합니다. Nasdaq 일정 시각은 미 동부 시간으로 보고 UTC로 바꿉니다.
- 지수와 금리는 미국 장 마감 기준 일별 값이라 최신 시장과 차이가 있을 수 있습니다. 5일 넘게 갱신되지 않은 값은 경고합니다. 뉴스는 날짜만 있고 시각은 없습니다.
- 해설 모델은 `macro.*` 지표와 그 방향 문장, 경제 일정, 기사 제목·요약을 받습니다. 해설에 쓰인 자료는 보고서의 출처에 OpenBB 기준일과 기사 제목·링크·날짜(최대 10개)로 남습니다.

## 판정 규칙과 해설 모델

판정은 코드가, 해설은 로컬 모델 하나가 맡습니다. 모델은 판정을 바꿀 수 없습니다.

### 판정 규칙 (`signals.py`, `rules-v2`)

| 주기 | 추세 | 돌파 | 거래량 | 청산(채점 기준) |
| --- | --- | --- | --- | --- |
| 4시간 추세 돌파 | 1d 20기간 변화율과 1d 종가의 SMA50 대비 위치가 같은 쪽 | 그 방향으로 4h 종가가 직전 20봉 고점 위(롱)·저점 아래(숏) | 4h 거래량이 직전 20봉 평균보다 많음 | 15m 종가 진입, 4h ATR 2배 익절·1배 손절 중 1h봉이 먼저 닿는 쪽, 최대 7일 |

세 조건이 모두 맞으면 롱 또는 숏, 하나라도 안 맞으면 관망입니다. `research.py`의 `breakout-volume`과 같은 함수입니다. 규칙을 바꾸면 `signals.VERSION`을 올려 채점이 섞이지 않게 합니다. 보고서에는 조건별 값(예: `4h 거래량: 평소의 0.562배 (부족)`)과 진입·익절·손절 가격이 들어갑니다.

**단타 판정을 뺀 이유 (`rules-v2`):** 단타는 같은 모양의 규칙(1시간 추세 + 15분 20봉 돌파 + 거래량)이었지만 익절·손절 없이 4시간 뒤 종가로 청산해 손익비 2:1이라는 매매법의 핵심이 빠져 있었습니다. 또 BTC 15분봉 ATR(약 0.16%)에서 왕복 수수료 0.1%가 약 60%를 차지했고, 연구 도구로 검증한 적도 없었습니다. 이전 단타 판정은 채점 표에 그대로 남습니다.

### 해설 모델 설정

1. LM Studio에 모델 하나를 설치하고 `models.json`의 `model`에 ID를 적습니다(`lms ls`로 확인). 기본값은 `huihui-qwen3.8-27b-abliterated`(Qwen 27B)입니다. 한국어 문장이 자연스러운 큰 모델이 좋습니다. 서버를 다시 시작하지 않아도 다음 분석부터 적용됩니다.
2. LM Studio 로컬 서버를 포트 1234로 실행하고 `python server.py` 후 **분석하기**를 누릅니다. **연결 및 구성** 화면에서 모델의 사용 가능 여부를 확인할 수 있습니다.

모델에는 판정, 규칙 이름, 조건별 값(`checks`), 청산 기준, 지표(`facts`)와 방향 문장(`signals`), OpenBB 거시 지표가 있으면 그 값, 경제 일정(`calendar`), 뉴스(`news`, 아래 "AI 정성 점검")를 보냅니다. 응답은 `summary`(판정 이유 한 문장), `risk`(규칙 밖의 위험), `review`(정성 점검 항목), `caution`(주의 수준)뿐이라 판정을 적을 칸이 없습니다. `summary`와 `risk`에 숫자가 있으면 경고만 표시합니다.

### AI 정성 점검

숫자로 된 지표 말고, 변동성이나 방향에 영향을 줄 만한 일정·뉴스·시장 분위기를 해설 모델이 점검해 **참고용**으로 보여줍니다. 판정은 바꾸지 않습니다. 과거 뉴스는 재현할 수 없어서, 이 점검이 성적을 올리는지 백테스트로 검증할 수 없기 때문입니다.

- **뉴스 출처:** `news.py`가 분석할 때마다 CoinDesk·Cointelegraph·Decrypt의 공개 RSS(키 없음)에서 분석 시각 전 48시간 안의 기사를 분 단위 시각과 함께 받습니다. 제목이 같은 기사는 하나만 남기고 최신 15개를 씁니다. 여기에 OpenBB(Nasdaq)의 날짜 단위 기사를 더합니다. 피드 하나가 실패하면 그 피드만 빠지고 경고에 남습니다. 해설 모델을 쓰지 않을 때(설정 오류, 백테스트)는 받지 않습니다.
- **점검 항목(`review`):** 최대 다섯 개. 항목마다 분류(일정·뉴스·시장 분위기), 내용, 영향(변동성 확대·상승 요인·하락 요인·영향 적음), 근거 기사를 적습니다. 근거 기사는 서버가 붙인 id(`news-1` 등)로만 인용할 수 있고(JSON 스키마 enum), 서버가 그 id를 제목·링크·시각으로 바꿔 보고서에 넣습니다. 없는 id를 적으면 해설 전체를 쓰지 않고 경고를 남깁니다.
- **주의 수준(`caution`):** 낮음·보통·높음. 이런 일정과 뉴스 때문에 지금 진입을 얼마나 조심해야 하는지에 대한 모델의 의견입니다.
- **화면:** 분석 데스크의 최종 판정 카드 아래 "AI 정성 점검" 카드에 주의 수준, 항목별 분류·영향 태그, 근거 기사 링크가 나오고, 종합 의견 카드에 "AI 주의" 태그가 붙습니다.
- **한계:** 기사 제목과 요약만 읽습니다(본문 없음). 영향 판단은 모델의 해석이며 검증되지 않았습니다. RSS 형식이 바뀌면 그 피드는 빠집니다.

### 분석 흐름

1. 시장 스냅샷을 수집하고 `indicators.py`가 마감 봉으로 지표를 계산합니다. 간격별 SMA 20·50·200과 이동평균 대비 위치, RSI 14(Wilder), ATR 14와 ATR %, 1봉·20봉 변화율, 직전 20봉 고저(마지막 봉 제외, 돌파 판정용), 거래량 비율(직전 20봉 평균 대비), 그리고 펀딩비율 %, 마크-인덱스 프리미엄 %, 미결제약정입니다. 계산값은 스냅샷과 함께 SQLite에 저장되고 수집 표에도 표시됩니다.
   분석을 실행할 때는 수급 이력도 함께 가져옵니다(`Collector.derivatives`). 최근 펀딩 21회(약 7일), 1h·4h 기간별 최근 25개의 미결제약정, 전체 계정 롱숏 비율, 대형 트레이더 포지션 롱숏 비율, 테이커 매수/매도 비율입니다. 시각 순서·종목·숫자를 검증하고 SQLite `derivatives` 테이블에 저장합니다. 여기서 펀딩 평균·최소·최대·양수 비율, OI 1·24기간 변화율, 롱숏 비율과 24기간 변화, 테이커 비율과 24기간 평균을 계산합니다. 해설 모델은 4h 값과 1h 값을 함께 받습니다. 60초 자동 수집에는 포함하지 않아 요청 수를 늘리지 않습니다.
2. `signals.py`가 주기별로 판정하고 조건별 값과 청산 기준을 문장으로 만듭니다.
3. 해설 모델을 한 번 호출합니다(이 PC에서 약 35초). 실패·시간 초과·잘린 응답·형식 오류면 경고를 남기고 코드가 쓴 문장으로 보고서를 완성합니다. 판정은 그대로입니다. `models.json`을 읽지 못해도 같은 식으로 규칙 판정만 냅니다.
4. 보고서를 SQLite에 저장하고 분석 데스크에 표시합니다.

### 한계와 안전장치

- 해설은 판정을 바꾸지 못하지만, 해설 문장 자체가 맞는지는 검증하지 않습니다. 판정이 수익으로 이어지는지도 보장하지 않습니다.
- 수급 이력은 분석할 때만 최근 25기간(1h·4h)과 최근 펀딩 21회를 가져옵니다. 장기 백필은 아직 없습니다.
- 모델 호출은 `http://127.0.0.1:1234/v1`로 고정하며 프록시와 리다이렉트를 사용하지 않습니다. 응답 제한은 600초이고, 거절되면 한 번 다시 시도합니다. `reasoning_effort: "none"`을 보내 추론 모델이 생각 과정에 출력 한도를 쓰지 않게 합니다.
- 서버당 한 번에 하나의 분석만 실행합니다. 진행 상황은 서버가 기록하므로 다른 창에서도 보이고, 진행도는 그 모델의 직전 소요 시간(`data/llm_timings.json`)을 기준으로 한 추정치입니다. 다른 창에서 시작한 분석이 끝나면 **결과 불러오기**로 가져올 수 있습니다. 서버를 다시 시작하면 마지막 보고서는 사라집니다.
- API: `GET /api/llm` 해설 모델 상태, `POST /api/analyze` JSON `{"symbol":"BTCUSDT"}`, `GET /api/progress` 진행 상황, `GET /api/last-report` 마지막 완료 보고서, `GET /api/scores` 버전·기간별 채점, `GET /api/backtests` 최근 백테스트 100건의 시점별 판정과 결과, `GET /api/backtests?id=…` 백테스트 보고서 하나(기간별 `outcome` 포함).

### 백테스트·규칙 연구·채점

- 백테스트: `python backtest.py --symbol BTCUSDT --days 90` (선택: `--every-hours 8`, `--limit 20`). LM Studio가 필요 없습니다. 4시간 경계의 과거 시점마다 그 시점 **이전에** 마감된 캔들(5m~1d)만으로 스냅샷을 만들어 실시간과 같은 `analyze()`를 모델 없이 돌리고, `mode='backtest'`로 저장해 실시간 판정과 섞이지 않게 채점합니다. 판정이 모델에 의존하지 않으므로 백테스트 성적이 곧 실시간에 같은 규칙이 냈을 성적입니다. 시점 하나에 1초 안팎이 걸립니다(이전 구조는 약 4~5분). 규칙은 캔들만 읽으므로 펀딩·미결제약정·롱숏 이력은 받지 않습니다. 그래서 Binance 아카이브에 빈 구간이 있어도 시점을 건너뛰지 않습니다. 아카이브(`data.binance.vision` 일별 5분 미결제약정·롱숏 비율, `data/archive/`에 한 번만 받아 둠)는 이제 `research.py`의 수급 규칙 후보만 씁니다. 아카이브 값은 같은 시각 REST 값과 1시간 기준 약 0.3% 이내로 다르고, 가끔 0인 행(예: 2026-10-15의 OI)은 30분 안의 직전 값으로 대신합니다. 최근 시점부터 거꾸로 적용하고, 같은 규칙 버전으로 이미 저장한 시점은 건너뜁니다. 스윙 채점이 끝나야 하므로 최근 3일은 제외됩니다.
- 백테스트 보기: 판단 이력의 "백테스트 판정" 표에 최근 100건의 시점, 판정과 결과(적중·빗나감과 수익률, 채점 대기, 가격 없음)가 나옵니다. "보고서 열기"를 누르면 분석 데스크에서 조건별 값과 청산 기준을 볼 수 있습니다. 가격 배율 열은 모델이 판정하던 이전 버전 보고서에만 값이 있습니다.
- 4시간봉 규칙 연구: `python research.py --symbol BTCUSDT --days 180` (선택: `--tp 1 1.5 2`, `--sl 1 1.5`, `--trail 2 3`, `--hold-hours 12 24`, `--fee 0.1`, `--min-trades 30`, `--top 30`). 모델을 돌리지 않고, 과거 4시간봉 마감마다 실시간 판정과 같은 서버 지표(`indicators.compute`, 1h·4h·1d 캔들과 아카이브 수급)를 계산해 규칙 후보가 롱·숏·진입 안 함을 정합니다. 진입가는 4시간 종가이고, 1시간봉으로 목표가(4시간 ATR × tp)와 손절(× sl) 중 먼저 닿는 쪽에서 청산하며, 둘 다 안 닿으면 최대 보유 시간 뒤 종가로 청산합니다. 한 봉에서 둘 다 닿으면 손절로 봅니다. 왕복 수수료를 뺀 순수익이 0보다 크면 적중입니다. 시점의 앞 2/3(학습)과 뒤 1/3(검증)을 나눠 보여주므로, 학습 구간에서 고른 규칙이 검증 구간에서도 버티는지 봅니다. 180일(1,080개 시점)이 약 20초 걸립니다(아카이브는 처음 한 번만 받음). `--trail`을 주면 같은 규칙을 목표가 없는 ATR 추적 손절(진입 후 가장 유리했던 가격에서 4시간 ATR × trail 만큼 떨어진 곳, 손절선은 되돌아가지 않음)로도 채점해 결과에 `추적·배수`로 표시합니다. 추세를 몇 주씩 들고 가는 방식은 고정 목표가로 채점하면 큰 이익이 잘리므로 `--hold-hours 24 168 720`처럼 긴 보유 시간과 함께 씁니다. 모든 신호를 채점하면 4시간마다 신호가 나와 거래가 겹치므로, 같은 거래를 한 번에 한 포지션만 드는 것으로 다시 돌린 "단일 포지션" 결과(진입 수·복리 누적 수익·최대 낙폭, 레버리지 없음)를 구간마다 함께 보여주고, 결과는 학습 구간의 단일 포지션 누적 수익 순으로 정렬합니다. 한계: 단일 포지션도 수수료 외의 슬리피지·펀딩비는 빼지 않고, 학습·검증 구간을 따로 처음부터 돌립니다. `--chart 규칙 TP SL 보유`(예: `--chart breakout-volume 2 1 168`, `--chart trend 추적 3 168`, `--chart 4bc 밴드 밴드 720`)를 주면 그 조합을 한 포지션씩 든 거래를 1시간봉 차트(한국 시간)에 진입·청산 표시와 진입 때 정한 익절·손절선으로 그려 `reports/chart-종목-규칙.html`에 저장합니다. 아래 거래 표의 행을 누르면 그 거래로 이동합니다. 추적 손절은 처음 손절 위치만 그립니다. 현재 스윙 규칙은 BTC·ETH·SOL 2년을 한 포지션씩 돌렸을 때 가장 고르게 이익이었던 `breakout-volume`입니다: 1일 20기간 변화율과 1일 종가의 SMA50 대비 위치가 같은 쪽일 때만 그 방향으로, 4시간 종가가 직전 20봉 고점 위(롱)·저점 아래(숏)로 나가고 4시간 거래량이 평소(20봉 평균)보다 많으면 진입합니다. 청산은 진입가에서 4시간 ATR 2배 익절·1배 손절, 최대 7일 보유(1위) 또는 1일 보유(2위)입니다. 실시간 판정과 백테스트는 이 규칙을 `signals.py`에서 그대로 씁니다(`research.RULES['breakout-volume']`도 같은 함수를 부릅니다. 이전 규칙은 `trend-200`). 판정 채점도 같은 익절·손절과 최대 7일 보유로 바꿨습니다(아래 채점 항목). 목표보다 손절이 넓으면 적중률은 오르지만 평균 순수익을 같이 봐야 합니다. 규칙 후보는 `research.RULES`에 추가하고, 연구에서 고른 규칙은 `signals.py`로 옮긴 뒤 `signals.VERSION`을 올립니다. 4BC 매매법(영상 「일반인도 쉽게 써먹는 4BC 매매법」 기준)은 4시간봉 CCI가 −100 아래로 내려갔다가 다시 위로 넘으면 롱, +100 위에서 다시 아래로 넘으면 숏으로 진입하고, 볼린저 밴드는 진입 조건이 아니라 청산에만 씁니다: 절반은 중앙선(20 이평), 나머지는 반대쪽 밴드에서 익절하고, 진입 쪽 밴드(롱은 하단, 숏은 상단)에서 손절하며, 남은 물량은 최대 보유 시간 뒤 종가로 청산합니다. CCI 20·볼린저 20/2σ(TradingView 기본값)이고, `4bc`는 4시간 교차만, `4bc-mtf`는 영상 4단계처럼 1시간·15분 CCI도 같은 선을 이미 넘어 같은 방향으로 움직일 때만 진입합니다. 이 두 규칙은 `--tp`·`--sl` 대신 밴드로 채점해 결과에 `밴드·밴드`로 표시되고, 같은 진입을 ATR 목표·손절로 채점한 `cci-cross`와 비교할 수 있습니다. 한계: 밴드 값은 진입 봉에서 고정해 쓰고(실제 밴드는 봉마다 움직임), 진입가가 이미 손절 밴드 밖이거나 중앙선을 넘었으면 진입하지 않으며, 영상의 매물대 손절·거래량을 보고 하는 익절 판단과 낮은 시간봉으로 4시간 마감 전에 먼저 들어가는 진입은 넣지 않았습니다. BTC 2년(보유 12·24·48시간) 결과는 `4bc`가 학습 217회·적중률 40~46%·평균 순수익 −0.19~0.00%, 검증 123회·−0.07~+0.17%, `4bc-mtf`가 학습 67회·+0.08~+0.19%, 검증 26회·적중률 35~42%·−0.24~+0.17%로, 두 규칙 모두 구간마다 결과가 달라 안정적인 우위로 보기 어렵습니다(`4bc-mtf`는 검증 진입이 적음).
