# BTC Agents Team · Futures Desk

Binance 코인 선물의 **단타와 스윙을 별도로 분석하고, AI 팀원들의 판정과 근거를 GUI에서 검토**하는 프로젝트입니다. 자동 주문보다 사람이 분석 과정을 확인하는 경험을 우선합니다.

> **현재 상태: 실제 시장 데이터 수집 + LM Studio 로컬 AI 분석.** Binance 공개 API의 체결가·마크 가격·펀딩비율·미결제약정·마감 캔들을 수집해 로컬 SQLite에 저장합니다. LM Studio의 역할별 로컬 모델로 수동 분석하며, 모델이 인용한 수치는 서버가 계산한 지표와 대조합니다. 첫 화면은 데모이며 분석 버튼으로 생성한 결과만 실제 수집값을 사용합니다. OpenBB로 미국 금리·지수·경제 일정·뉴스를 받아 뉴스·거시 분석가(EXAONE)가 판단합니다. 판정 채점과 백테스트는 아직 없습니다. 도구별 상태는 아래 "도구 구성"을 참고하세요.

## 목표와 현재 결정

- 거래소: Binance. 화면은 USDⓈ-M 무기한 선물을 기준으로 설계했습니다. 현재 차트와 동일한 BTCUSDT·ETHUSDT·SOLUSDT USDT 무기한부터 읽기 전용 수집을 구현했습니다.
- 분석 주기: 단타와 스윙을 모두 제공하고 서로 다른 의견을 그대로 보여줍니다.
- 모델: LM Studio의 역할별 로컬 모델을 사용합니다. GPT 등 클라우드 모델은 연결 계획이 없습니다.
- 투명성: 팀원별 판정, 근거, 반론, 판단을 철회할 조건, 자료 기준 시각을 표시합니다.
- 자동 주문: 현재 범위에 포함하지 않습니다.
- TradingAgents(TauricResearch/TradingAgents)는 연결하지 않고, 팀 분석을 직접 구현했습니다.

## 빠른 시작

Python 3.10 이상과 표준 라이브러리로 로컬 서버를 실행합니다. 별도 pip/npm 패키지 설치나 빌드는 필요 없습니다.

```sh
git clone https://github.com/weri200/btc-agents-team.git
cd btc-agents-team
python server.py
```

브라우저에서 `http://127.0.0.1:8876`을 엽니다. 포트를 바꾸려면 `python server.py --port 8877`을 사용하세요. 같은 포트를 이미 다른 서버가 쓰고 있으면 서버가 오류 메시지를 내고 종료합니다. Windows에서 두 서버가 같은 포트에 겹쳐 뜨는 것을 막기 위해서입니다. 단순 정적 서버나 파일 직접 열기로는 수집 API가 동작하지 않습니다. 보고서 이력과 테마 설정은 주소·포트별 브라우저 저장소에 보관됩니다.

검사에는 Node.js가 필요합니다. 별도 npm 의존성은 없습니다.

```sh
node test.cjs
node test_market_ui.cjs
node test_opinions.cjs
python -m unittest -v test_market.py test_local_llm.py test_indicators.py
node --check dist/app.js
node --check dist/model.js
node --check dist/market.js
```

예시 보고서와 판정 집계, 실제 분석 보고서 형식, 잘못된 날짜·판정·URL·중복 팀원 ID 등의 거절을 검사합니다.

단타의 5분/15분/1시간, 스윙의 4시간/1일 봉은 **초기 화면 가정**입니다. 검증된 전략이나 확정된 분석 주기가 아닙니다.

## 보고서 형식

전체 예시는 `example-report.json`, 검증 규칙은 `dist/model.js`의 `validate()`를 확인하세요.

- `schemaVersion`: `1`
- `id`, `symbol`, `asOf`, `promptVersion`: 보고서 식별 정보
- `exchange`: `Binance`
- `market`: `USDⓈ-M perpetual`
- `mode`: `demo` 또는 `analysis`
- `horizons.intraday`, `horizons.swing`: 두 주기의 독립된 보고서
- 주기별 `verdict`, `summary`, `agreement`, `disagreement`, `condition`, `agents`
- 팀원별 `id`, `name`, `role`, `verdict`, `summary`, `evidence`, `counter`, `invalidation`, `model`, `sources`
- 판정: `long`, `short`, `wait`
- 출처: `title`, `url` (HTTP/HTTPS 또는 null), `asOf`

날짜에는 시간대가 필요하며 UI는 한국 시간으로 표시합니다. `mode: analysis`는 파일 작성자의 선언일 뿐, 실제 AI 실행이나 내용 정확성을 인증하지 않습니다. 파일은 최대 500KB이며 가져오기는 서버 업로드 없이 브라우저에서 처리합니다.

## 검증의 한계

GUI와 입력 검증이 동작해도 매매 전략의 수익성을 의미하지 않습니다. 다수 의견이나 모델의 자신감은 승률이 아닙니다. 과거 공개 시각, 미래 정보 유입, 거래 비용과 선물 청산 위험을 검증해야 합니다. 실제 투자 및 자동 주문에 바로 사용할 수 있는 상태가 아닙니다.

## 시장 차트

TradingView 공식 Advanced Chart 위젯으로 Binance USDT 무기한 BTC·ETH·SOL 차트를 제공합니다. 봉 간격은 1분·5분·15분·1시간·4시간·1일·1주이며 한국 시간으로 표시됩니다. 인터넷 연결 및 외부 위젯 제공 상태에 의존합니다. 차트 선택은 데모 보고서 선택과 독립적이며 차트 데이터로 AI 판정을 생성하지 않습니다. 테마를 실제로 바꿀 때만 차트를 다시 불러옵니다. 예전에는 페이지를 열 때 같은 테마가 다시 설정되면서 차트가 두 번 만들어졌고, 첫 차트가 불러오는 중에 지워져 가격·시간 축이 잘리는 일이 있었습니다.

차트 위의 **지표** 메뉴에서 이동평균(SMA), EMA, 볼린저 밴드, VWAP, RSI, MACD, 스토캐스틱 RSI, ATR, 일목균형표를 고를 수 있습니다. 고른 지표는 브라우저에 저장되고(`futures-desk-studies`), RSI·MACD처럼 아래에 별도 창이 생기는 지표를 고르면 그 수만큼 차트가 높아집니다. 목록에 없는 지표는 차트 위쪽 툴바의 TradingView 지표 버튼으로 추가할 수 있지만, 새로고침하면 사라집니다. 차트 지표는 화면 표시용이며 AI 분석에 쓰는 지표는 서버가 따로 계산합니다.

## 실제 수집 데이터 — 1단계

- `GET /api/market?symbol=BTCUSDT` (ETHUSDT·SOLUSDT도 지원). API 키 없이 공개 시장 데이터만 읽습니다.
- `/fapi/v1/time`, `/fapi/v2/ticker/price`, `/fapi/v1/premiumIndex`, `/fapi/v1/openInterest`, `/fapi/v1/klines`를 사용합니다.
- 차트 코인을 선택하면 수집 종목도 바뀝니다. 분석 데스크가 보이는 동안 60초마다 갱신하고, 같은 종목은 30초 동안 캐시합니다. 수동 버튼으로도 요청할 수 있습니다. 브라우저를 닫으면 주기 수집이 중단됩니다.
- 5분·15분·1시간·4시간·1일 봉을 각 최대 200개 가져옵니다. 거래소 기준 시각 이전에 마감된 봉만 저장하며, 중복·누락·순서·OHLC·숫자 유효성을 검사합니다. 진행 중인 봉은 제외합니다.
- 가격·수량·비율은 API의 십진수 문자열을 보존합니다. UI는 펀딩비율에 100을 곱해 %로 표시합니다. 펀딩비율은 API의 `lastFundingRate`이며 실제 계좌 지불액이나 확정된 다음 정산율로 간주하지 않습니다. OI 단위는 해당 기초 코인입니다.
- 항목별 거래소 시각, PC 수집 시각, 수집 소요시간, PC-거래소 시계 차이를 기록합니다. 서로 다른 요청이므로 모든 항목이 동일 시점의 원자적 스냅샷은 아닙니다. 오래된 수급·시계 차이·수집 지연은 경고합니다.
- `data/market.sqlite3`의 `candles`는 종목·간격·시작시각으로 중복 저장을 막고, `snapshots`에는 수집 이력과 시세·수급을 저장합니다. 한 번의 수집은 트랜잭션으로 저장하며 부분 실패는 성공으로 취급하지 않습니다. DB는 Git에서 제외됩니다.
- 네트워크 실패·429/418 요청 제한·저장 실패는 화면에 오류로 표시합니다. 제한 시 Retry-After 동안 재호출을 막습니다. 과거 수치를 새 값으로 대체하거나 데모 데이터를 실제 데이터로 반환하지 않습니다.
- 로컬 서버는 127.0.0.1에만 바인딩하며 외부 Origin·Host와 저장 DB의 웹 접근을 거절합니다.
- 아직 없는 기능: 과거 전체 이력 백필, 장기 펀딩/OI 시계열 백필, 뉴스 수집, 주문, 백테스트. 최근 200개 봉 수집을 장기간 전략 검증용 완전한 데이터셋으로 간주하지 않습니다.

공식 API 근거: https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data

## 의견 표시

데스크톱에서는 차트 오른쪽에 단타·스윙 종합 의견을 표시하고, 좁은 화면에서는 차트 아래로 배치합니다. 팀원 카드에는 판단·첫 번째 근거·재검토 조건을 3개 항목으로 표시하며 긴 문장은 줄바꿈합니다. 전체 근거와 반론은 상세 창에서 확인할 수 있습니다. 차트와 보고서 종목이 다른 경우 안내하며 데모·파일 보고서·로컬 모델 결과를 구분합니다. 로컬 모델 결과는 생성 시점의 스냅샷이며 자동 갱신되지 않습니다.


## OpenBB 뉴스·거시 자료

OpenBB는 서버 의존성이 아닙니다. 프로젝트 안의 가상환경(`.venv`, Git 제외)에 설치하고, 서버가 분석할 때 `openbb_bridge.py`를 그 가상환경의 Python으로 따로 실행해 결과(JSON)만 받습니다. 서버는 계속 표준 라이브러리만으로 동작하며, OpenBB가 없거나 실패해도 나머지 팀은 그대로 분석하고 뉴스·거시 분석가만 관망과 이유를 표시합니다.

```sh
python -m venv .venv
.venv\Scripts\python -m pip install openbb
```

macOS·Linux에서는 `.venv/bin/python`을 씁니다. 다른 위치의 Python을 쓰려면 환경 변수 `OPENBB_PYTHON`에 경로를 지정합니다. 처음 실행할 때 OpenBB가 확장을 빌드하느라 시간이 더 걸리고, 이후에도 불러오는 데 약 15~20초가 걸립니다.

API 키가 필요 없는 공급자만 사용합니다(OpenBB 5.0 기준 공급자별 명령).

| 자료 | 공급자 · 명령 | 서버가 만드는 지표 |
| --- | --- | --- |
| 미국 2년·10년 국채 금리 | Fed `federal_reserve.treasury_rates` | `macro.us2yPct`, `macro.us10yPct`, 5일 변화(bp), 10년-2년 금리차 |
| VIX, S&P500 | CBOE `cboe.index.historical` | `macro.vix`, 1일·5일 변화율 |
| 나스닥100 | Nasdaq `nasdaq.index.historical` | 1일·5일 변화율 |
| 경제 일정 | Nasdaq `nasdaq.economy.calendar` | 분석 시각 전 24시간~후 72시간의 미국 주요 지표(CPI·고용·FOMC·GDP 등) |
| 뉴스 | Nasdaq `news.company` (IBIT·COIN, ETH는 ETHA, SOL은 BSOL) | 최근 7일, 코인 관련 단어가 있는 기사 최대 8개 |

- 일별 자료는 분석 시각(Binance 서버 시각)의 날짜 이후 값을 버립니다. 경제 일정은 분석 시각 이후 항목의 발표 결과를 지우고 "예정"으로만 넘겨, 미래 정보가 들어가지 않게 합니다. Nasdaq 일정 시각은 미 동부 시간으로 보고 UTC로 바꿉니다.
- 지수와 금리는 미국 장 마감 기준 일별 값이라 최신 시장과 차이가 있을 수 있습니다. 5일 넘게 갱신되지 않은 값은 경고합니다. 뉴스는 날짜만 있고 시각은 없습니다.
- 뉴스·거시 분석가는 `macro.*` 지표만 인용할 수 있고, 기사는 서버가 붙인 id(`news-1` 등)로만 인용할 수 있습니다(JSON 스키마 enum). 인용한 기사는 보고서의 출처에 제목·링크·날짜로 남습니다. 반대 검토자는 거시 지표도 함께 봅니다.
- 실제 실행(2026-10-23, BTCUSDT): 처음에는 EXAONE의 인용이 6개 중 1개만 맞았습니다. 지표를 `macro.*`로 좁히고 근거 항목 순서를 `ref → value → claim`으로 바꾼 뒤 세 번 실행에서 19개 중 18개가 맞았고, 틀린 1개는 검증에서 관망 처리됐습니다.

## LM Studio 로컬 모델팀

역할마다 다른 로컬 모델이 분석하고, 모델이 인용한 수치를 서버가 직접 계산한 지표와 대조합니다.

### 설정

1. LM Studio에 역할별 모델을 설치합니다. 기본값은 VRAM 16GB 기준 추천 구성입니다. 분석가 세 명은 서로 다른 계열의 12~14B 모델을 쓰고, 지표 없이 의견만 종합하는 판정자는 이미 설치된 27B 모델을 씁니다. 정확한 모델 ID는 설치 후 `lms ls`로 확인합니다.
2. `models.json`의 `roles`에 역할별 모델 ID를 적습니다. 서버를 다시 시작하지 않아도 다음 분석부터 적용됩니다.

   | 역할 | 키 | 기본값 (추천 계열) |
   | --- | --- | --- |
   | 기술 분석가 | `technical` | `mistralai/mistral-nemo-instruct-2407` (Mistral Nemo 12B) |
   | 파생상품 분석가 | `derivatives` | `microsoft/phi-4` (Phi-4 14B) |
   | 뉴스·거시 분석가 | `macro` (선택) | `exaone-3.5-7.8b-instruct` (EXAONE 3.5 7.8B, LG, 비상업 라이선스) |
   | 반대 검토자 | `critic` | `google/gemma-4-12b` (Gemma 4 12B) |
   | 종합 판정자 | `judge` | `huihui-qwen3.8-27b-abliterated` (설치됨, Qwen 27B) |

3. 모델 네 개를 동시에 VRAM에 올릴 수 없으므로 LM Studio Developer 설정에서 **JIT 모델 로딩**과 **사용하지 않는 JIT 모델 자동 해제**를 켭니다. 요청한 모델 ID를 LM Studio가 차례로 불러옵니다.
4. LM Studio 로컬 서버를 포트 1234로 실행하고 `python server.py` 후 **로컬 모델팀으로 분석**을 누릅니다. **연결 및 구성** 화면에서 역할별 모델의 사용 가능 여부를 확인할 수 있습니다.

같은 모델을 여러 역할에 적으면 동작하지만 의견의 독립성이 낮다는 경고를 표시합니다. 설치되지 않은 모델이 있으면 분석을 시작하지 않고 해당 역할과 모델 ID를 알려줍니다.

### 분석 흐름

1. 시장 스냅샷을 수집하고 `indicators.py`가 마감 봉으로 지표를 계산합니다. 간격별 SMA 20·50·200과 이동평균 대비 위치, RSI 14(Wilder), ATR 14와 ATR %, 1봉·20봉 변화율, 20봉 고저, 거래량 비율(직전 20봉 평균 대비), 그리고 펀딩비율 %, 마크-인덱스 프리미엄 %, 미결제약정입니다. 계산값은 스냅샷과 함께 SQLite에 저장되고 수집 표에도 표시됩니다.
   분석을 실행할 때는 수급 이력도 함께 가져옵니다(`Collector.derivatives`). 최근 펀딩 21회(약 7일), 1h·4h 기간별 최근 25개의 미결제약정, 전체 계정 롱숏 비율, 대형 트레이더 포지션 롱숏 비율, 테이커 매수/매도 비율입니다. 시각 순서·종목·숫자를 검증하고 SQLite `derivatives` 테이블에 저장합니다. 여기서 펀딩 평균·최소·최대·양수 비율, OI 1·24기간 변화율, 롱숏 비율과 24기간 변화, 테이커 비율과 24기간 평균을 계산합니다. 1h 값은 단타, 4h 값은 스윙에 씁니다. 60초 자동 수집에는 포함하지 않아 요청 수를 늘리지 않습니다.
2. 기술 분석가 → 파생상품 분석가 → 뉴스·거시 분석가(macro 설정과 OpenBB 자료가 있을 때) → 반대 검토자 순서로 각자의 모델을 호출합니다. 모델에는 원본 봉 대신 계산된 지표(`facts`)와, 서버가 각 지표의 방향(위/아래, 증가/감소, 우위)을 한국어 문장으로 옮긴 `signals`를 전달합니다. 단타는 `market.*`와 5m·15m·1h, 스윙은 `market.*`와 4h·1d 키만 받습니다. 역할별로도 나눕니다. 기술 분석가는 가격 지표만, 파생상품 분석가는 펀딩·OI·롱숏·테이커 지표와 가격 변화율·거래량 비율만, 반대 검토자는 전부를 받습니다. 반대 검토자는 앞의 두 의견도 함께 받습니다.
3. 근거마다 `ref`(지표 키)와 `value`(값)를 적게 합니다. `ref`는 JSON 스키마의 enum으로 제한해 없는 지표를 지어낼 수 없습니다.
4. 서버가 `value`를 실제 계산값과 대조합니다. 0.5% 이내이거나, 실제 값을 인용한 유효숫자(2자리 이상)로 반올림한 값과 같으면 일치로 봅니다. 하나라도 틀리면 그 의견의 판정을 **관망으로 바꾸고** 원래 판정을 함께 기록합니다. 문장에 검증하지 않은 숫자가 있으면 경고만 표시합니다.
5. 종합 판정자는 지표 없이 팀원 의견과 검증 결과만 받아 종합 판정·공통 의견·이견·재검토 조건을 씁니다. 팀원 누구도 지지하지 않은 롱/숏 판정은 관망으로 바꿉니다.

### 한계와 안전장치

- 수치 검증은 인용한 값이 맞는지만 확인합니다. 해석이 옳은지, 판정이 수익으로 이어지는지는 검증하지 않습니다.
- 수급 이력은 분석할 때만 최근 25기간(1h·4h)과 최근 펀딩 21회를 가져옵니다. 장기 백필은 아직 없습니다. 뉴스·거시 자료는 위 "OpenBB 뉴스·거시 자료"를 참고하세요.
- 모델 호출은 `http://127.0.0.1:1234/v1`로 고정하며 프록시와 리다이렉트를 사용하지 않습니다. 호출당 응답 제한은 600초이고, JIT 모델 교체 중 거절에 대비해 한 번 다시 시도합니다. 모든 요청에 `reasoning_effort: "none"`을 보내 Gemma 4 같은 추론 모델이 생각 과정에 출력 한도를 쓰지 않게 합니다. LM Studio가 거절하면 그 오류 메시지를 표시합니다.
- 이 PC(RX 9070 XT 16GB)에서 BTC·ETH 실제 분석은 모델 교체를 포함해 약 3~5분 걸렸습니다. 서버당 한 번에 하나의 분석만 실행합니다.
- 실패·시간 초과·잘린 응답·형식 오류는 실패한 역할과 모델 ID를 표시하고 기존 보고서를 덮어쓰지 않습니다.
- 보고서에는 역할별 모델 ID(`team`), 계산된 지표(`facts`), 팀원별 검증 결과(`verification`)가 포함되어 JSON으로 내보낼 수 있습니다.
- 진행 상황: 분석 중에는 역할별 카드의 테두리와 모델 로고 둘레가 12시 방향부터 시계방향으로 차오릅니다. 진행도는 그 모델의 직전 소요 시간(`data/llm_timings.json`, 처음에는 60초)을 기준으로 한 **추정치**이고, 서버가 완료를 알리기 전까지 95%에서 멈춥니다. 완료는 초록, 실패는 빨강입니다. 로고는 공급사를 구분하기 위한 단순화한 표시이며 공식 로고 파일이 아닙니다.
- 진행 상황은 서버가 기록하므로 다른 브라우저 창에서도 보입니다. 다른 창에서 시작한 분석이 끝나면 **결과 불러오기**로 그 보고서를 가져올 수 있습니다. 서버를 다시 시작하면 마지막 보고서는 사라집니다.
- API: `GET /api/llm` 역할별 모델 상태, `POST /api/analyze` JSON `{"symbol":"BTCUSDT"}`, `GET /api/progress` 진행 상황, `GET /api/last-report` 마지막 완료 보고서. 구현: `local_llm.py`, `indicators.py`.
- 모델 API 참고: https://lmstudio.ai/docs/developer/openai-compat/structured-output
